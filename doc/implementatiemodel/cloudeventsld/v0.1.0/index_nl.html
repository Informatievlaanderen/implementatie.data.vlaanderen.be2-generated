Dit document beschrijft een implementatiemodel, in dit geval het implementatiemodel Implementatiemodel CloudEventsLD. Een implementatiemodel beschrijft het datamodel van een specifieke gegevensuitwisseling. Als de uitwisseling in een groep toepassingen valt waarvoor een applicatieprofiel bestaat, houdt dit een verdere selectie van termen in of het vaststellen van bijkomende restricties of uitbreidingen voor de specifieke toepassing en/of voor het specifieke platform van de gegevensuitwisseling.

Entiteiten

CloudEvent

Beschrijving
Een neerslag van een event dat plaatsvond in een bepaalde context.
Gebruik
Het RDF subject is een combinatie van het attribuut 'id' en zijn attribuut 'source'.
Eigenschappen
Voor deze entiteit zijn de volgende eigenschappen gedefinieerd: data , datacontenttype , id , specversion , subject , time , type .
Eigenschap Verwacht Type Kardinaliteit Beschrijving Gebruik Codelijst
data Inhoud 0..1 Beschouwd als een abstracte klasse omdat de inhoud alles kan zijn, beschreven door datacontenttype.
datacontenttype String 0..1 Mediatype van de inhoud van het event in het attribuut 'data' volgens RFC 2046. Bijvoorbeeld: application/json
id String 1 Herpublicatie van een duplicaat mag dezelfde source en id gebruiken, de waarde zelf is niet een globale unieke event IRI.
specversion String 1 Voor CloudEvents core 1.0.2 is de waarde '1.0' en niet '1.0.2'.
subject String 0..1 Dit is niet altijd een URI en mag dus niet zomaar gebruikt worden als dcterms:subject of een RDF resource zonder mapping.
time DateTime 0..1 Tijdstip waarop het event gebeurde. Tijdstip van het event op het terrein, niet het tijdstip waarop het event was aangemaakt of afgeleverd in de data.
type String 1 Soort event benaming gekozen door de dataproducent. Reverse-DNS prefixes zijn aangeraden. Dit is geen rdf:type omdat een CloudEvents type string niet automatisch een RDF klasse aangeeft.
